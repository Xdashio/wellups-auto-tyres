# v0.1 Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v0.1 foundation of the Well Lups Auto Tyres platform: a complete database layer (14 tables + 9 enums + RLS policies verified by pgTAP), Supabase Auth with 5-role access control, seed data, a Next.js 15 App Router TypeScript project on Cloudflare Workers via @opennextjs/cloudflare, Tailwind v4 design tokens, and a shared UI primitives library — all verified empirically before integration.

**Architecture:** Two parallel work streams (Backend + Frontend infra) that share no mutable code until the integration seam, then converge at a typed interface check before storefront wiring. Backend uses Supabase local dev (Docker); frontend scaffolds in the repo root.

**Tech Stack:** Next.js 15 (App Router, TypeScript), pnpm 9, Tailwind CSS v4, @opennextjs/cloudflare, Supabase CLI 2.x, PostgreSQL 15, pgTAP, Vitest, Playwright, Radix UI, Framer Motion, Zod, react-hook-form, lucide-react, clsx + tailwind-merge, Plus Jakarta Sans via next/font.

**Spec:** CLAUDE.md, PRD.md, ARCHITECTURE.md, TECH_STACK.md, DESIGN.md, CODE_STANDARDS.md, ROADMAP.md, INFO_NEEDED.md (all in docs/).

## Global Constraints

- Project is a SINGLE-BRANCH retailer: one `branches` row seeded (Industrial Area), no per-branch stock logic. `branches` table exists for future expansion. (ROADMAP.md §Phase 0, ARCHITECTURE.md §3, CORRECTION relative to original plan which seeded two branches)
- Roles are Admin / Manager / Cashier (NOT Owner — corrected from original plan). Plus Customer and Anon. (CLAUDE.md, CODE_STANDARDS.md §6)
- RLS is the enforcement source of truth. JWT `app_metadata.staff_role` is UX-only, never the auth gate. (CODE_STANDARDS.md §6, ADR-03)
- Cost price / margin columns denied to Cashier at the database layer via column-level grants — verified by logging in as an actual test Cashier account and confirming columns return no data, not by reading the grant statement. (CLAUDE.md, CODE_STANDARDS.md §6)
- Cloudflare Workers via @opennextjs/cloudflare (NOT Pages — Pages can't serve SSR/RSC). Requires `compatibility_flags=["nodejs_compat"]`, Next.js 15 (not 16/Turbopack — OpenNext doesn't support it yet). (ARCHITECTURE.md §1/§6, ADR-01)
- All enums: staff_role, product_status, order_status, booking_status, payment_method, fulfillment_type, price_type, category_type. (CODE_STANDARDS.md §4.6)
- Computed values (margin, line totals) are generated columns, not application arithmetic. (CODE_STANDARDS.md §4.5)
- All migrations are numbered, append-only SQL under supabase/migrations/. Never edit an applied migration. (CODE_STANDARDS.md §5)
- One policy per operation per table — never `for all`. Every policy names its role with `to`. (CODE_STANDARDS.md §5)
- `revoke all on schema public from public;` at the start of every migration. (CODE_STANDARDS.md §5)
- security-definer functions in `private` schema only, with `set search_path = ''`. (CODE_STANDARDS.md §5)
- Tailwind v4 — use `@theme` block in CSS, NOT tailwind.config.ts theme extension. (TECH_STACK.md, DESIGN.md §3)
- No God components; one component per file, under ~150 lines. (CODE_STANDARDS.md §4)
- TypeScript strict mode, no `any`. (CODE_STANDARDS.md §3)
- Zod for all data crossing trust boundaries. (CODE_STANDARDS.md §3)
- Conventional commits, one logical change per commit. (CODE_STANDARDS.md §9)
- Seed data ONLY in supabase/seed.sql, clearly marked as placeholder. (CODE_STANDARDS.md §5, §9)
- Open items from INFO_NEEDED.md are NOT assumed: M-Pesa Paybill/Till, WhatsApp Cloud API, real catalog data, domain name.

## Review Focus

| Failure mode | How a reasonable person expects it to behave | Owning task |
|---|---|---|
| Cashier sees cost price in POS | Should be blocked — Cashier role cannot read `cost_price`, `unit_cost`, `total_cost`, or `margin` columns | T1.5 (products), T1.6 (order_items) |
| Anon can write to any table | Should be denied for insert/update/delete on all tables except reviews (insert own) | T1.8 (pgTAP) |
| Customer sees other customers' orders | Should be blocked by `customer_id = auth.uid()` RLS | T1.8 (pgTAP) |
| Cost price drift in orders | `unit_cost` stored at order time, margin is generated column — never application-side arithmetic | T1.5, T1.6 |
| Role change not taking effect | RLS reads `private.current_staff_role()` from DB, not JWT — immediate effect | T1.8 (pgTAP) |
| OpenNext build fails on Turbopack | Next.js pinned to v15 with `--webpack` flag, wrangler.jsonc has `nodejs_compat` | T2.1 |
| UI primitive doesn't match schema type | Integration task checks ProductCard props against real Product row shape | T3.1 |
| pgTAP tests don't cover column-level denial | Tests explicitly SELECT cost_price as each role and assert denial | T1.8 |
| Seed data not clearly marked as placeholder | Seed file header says "PLACEHOLDER" and references INFO_NEEDED.md #2/#3 | T1.9 |

## Execution Method

**Recommendation: Subagent-driven execution with parallel thread dispatch.** This plan has 19 tasks across two independent threads (Backend T1-T12, Frontend T13-T16) that converge at Integration (T17-T19). The two threads share no mutable code until Task 17. This maps directly to `dispatching-parallel-agents`: dispatch Thread 1 and Thread 2 as two parallel subagents, each using `executing-plans` methodology (TDD per step, verification-before-completion gate, systematic-debugging for failures). After both threads complete, the parent orchestrates the integration tasks (T17-T19) with a final whole-branch review via `requesting-code-review`.

**If inline (executing-plans) is preferred instead:** Execute tasks sequentially in the order above, with TDD gates and verification before each completion claim. The ledger tracks progress at `.superpowers/sdd/2026-09-20-v0.1-implementation/progress.md`.

**Cost note:** Subagent-driven costs a fresh context per task + per review (19 tasks × 2 rounds = ~38 contexts). Inline costs one context + one final review. Given the two-thread parallelism requirement, subagent-driven is recommended.
